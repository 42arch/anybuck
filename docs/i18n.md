# 界面国际化

应用支持 `zh-CN`、`en-US` 和“跟随系统”。偏好保存在 `cloudstore-settings` 的 `language` 字段；`src/i18n/index.ts` 在 React 渲染前确定语言，并在切换时更新 `document.documentElement.lang`、窗口标题和 i18next。界面使用 `react-i18next`，非组件逻辑可直接调用 `i18n.t()`。

词条位于 `src/i18n/locales/zh-CN.json` 和 `en-US.json`。新增文案时，在两份文件中添加同名的、描述用途的键；完整句子使用插值参数，数量变化使用 i18next 的 `_one` / `_other` 复数形式。不要把对象名称、对象 Key 或云服务返回的原始错误写入词条。

词条按用途分组：通用操作放在 `common`，服务商名称放在 `providers`，传输阶段放在 `transferPhase`，页面和弹窗文案放在对应功能分组，例如 `fileDetails.publicFileLink`。修改文案时保持键名表达用途，并同步更新两种语言。

Rust 内部使用 `AppError { code, params, detail }`，不保存面向用户的整句诊断。`code` 是稳定的 camelCase 错误码，`params` 用于词条插值，`detail` 只保留系统或云服务返回的原始信息。Tauri 命令直接序列化此结构，前端通过 `src/api/invoke.ts` 翻译，兼容旧版后端返回的纯字符串。新增错误码时，同步更新两份 `backendErrors` 词条。传输任务持久化 `errorCode` 与原始 `error`；旧记录没有错误码时继续显示原文，可能包含旧版中文信息。兼容性检查逐项返回诊断码、参数及可选原始详情，由 `compatibilityDiagnostics` 词条翻译。
